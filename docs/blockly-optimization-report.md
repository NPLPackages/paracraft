# Blockly 编辑器优化分析报告

> 日期: 2026-07-03
> 背景: 用户(敲键盘的高老师/许剑文)反馈: ① 放大缩小定位不方便; ② 上下滑动不流畅、定位不准; ③ 代码太长, 不像 Scratch 可以多个头, 只有一个头就得很长。
> 分析范围: `script/ide/System/UI/Blockly/` 下的 Blockly.lua、ScrollBar.lua、Block.lua、Const.lua、ContextMenu.lua 等。

---

## 一、问题根因分析

### 1. "放大缩小定位不方便" —— 缩放没有锚点, 缩放后视口会"跳走"

- 缩放只能通过右下角的 +/- 图标按 0.1 步进 (`Blockly.lua` OnMouseDown 中 mousePosIndex == 2/3), **不支持 Ctrl+滚轮缩放, 也不支持触摸捏合**。
- 关键问题在 `Blockly:UpdateScale()`: 每次缩放后调用 `AdjustCenter()`(无参数), 而 `AdjustCenter` 的逻辑是找"视图中最左边的一个块", 把它挪到视口 1/3 宽、1/4 高的位置。**缩放不保持鼠标下的点或视口中心不动, 而是每次都跳到某个块附近**——用户正在看代码中段, 一点缩小, 视口直接飞到别处。
- `UpdateScale` 下方被注释掉的代码说明曾尝试过按比例重排块坐标, 后放弃改成了"跳最左块"方案。

### 2. "上下滑动不流畅、定位不准" —— 滚轮步长小、无平滑、滚动范围虚大、滚动条有 bug

**滚轮逻辑 (`Blockly:OnMouseWheel`)**:
- 每格滚轮只移动 `delta * 20` 逻辑像素, 且是缩放前坐标——缩小到 0.5 倍时视觉上每格只挪 10px, 代码越长、缩得越小, 滚动越"推不动"。
- 只支持纵向; 没有 Shift+滚轮横向滚动; 没有 Ctrl+滚轮缩放。
- 无平滑动画, 偏移被量化到 3px 网格 (UnitSize=3), 滚动一格格硬跳。
- 漏调 `self:OnOffsetChange()`——对比拖拽平移有调用, 滚轮滚动后注释(Note)的窗口位置不更新(隐藏 bug)。

**滚动范围 (`Blockly:AdjustContentSize`)**:
- `content_offset = -1000`(单元)的魔法数让内容四周各多出约 3000px 可滚动空白。后果:
  1. 孩子拖拽平移时容易把代码"滑丢"到大片空白里;
  2. 滚动条滑块行程被 6000px 空白稀释, 内容只占行程的一小段, 无法精确定位。

**横向滚动条两个 bug (`ScrollBar.lua`)**:
- 滑块宽度公式缺括号: `width * width / count * UnitSize`(应为 `width * width / (count * UnitSize)`, 对比纵向公式), 横向滑块被放大 UnitSize² = 9 倍, 经常比轨道还宽, 偏移变负数, 显示错乱。
- 方向不一致: 纵向滑块位置用 `(1 - ratio)` 做了反转, 横向没有——由于 offsetX/offsetY 语义相同(内容平移量), 横向滑块的拖动方向与内容移动方向相反。
- 滑块无最小尺寸限制, 内容一长滑块细到点不中。

**性能(长代码必卡)**:
- `Blockly:RenderContent` 每帧全量绘制所有块, `Block:Render` 沿 next 链递归画完整条堆栈, **没有任何视口裁剪**; 每个顶层块画完还 `painter:Flush()` 一次; 小地图开启时再全量画一遍。运行块闪烁计数逻辑说明渲染是逐帧的, 长代码帧率必然下降。
- 撤销机制 (`Blockly:Do/Undo/Redo`) 每次变更都把整个工作区序列化成 XML 文本存快照, 撤销时清空全部块再整体重建。长代码时每拖一个块都有一次全量序列化开销。

### 3. "只有一个头" —— 引擎其实支持多头, 是呈现和教学问题

- `Blockly:GetCode()` 支持任意多个顶层堆栈: 所有"没有上连接、有下连接"的块都被当作开始块, 代码全部拼接生成; npl 语言配置里有 `registerClickEvent` / `registerKeyPressedEvent` / `registerBroadcastEvent` 等事件帽子块, 可以事件驱动多头并行。
- 折叠功能已存在 (FoldedBlock + 右键"折叠|展开块"); 小地图支持点击跳转定位, 但默认隐藏。
- 问题在于:
  1. 多个普通顶层堆栈按内部数组顺序顺序拼接执行, 不是 Scratch 的"每头独立并行", 执行顺序与视觉位置无关, 用户不敢拆;
  2. 事件帽子块在工具箱不突出, 教学上没形成"一个事件一个头"的习惯;
  3. 折叠藏在右键菜单里; 没有"一键整理布局"。

## 二、解决方案

### P0 (已实施, 见本次提交)

1. **滚轮体验重做** (`Blockly:OnMouseWheel`)
   - 步长按行高且补偿缩放: `delta * LineHeightUnitCount * UnitSize * 3 / scale`, 视觉步长恒定约 3 行;
   - 平滑滚动: 滚轮只更新目标偏移, 每帧向目标插值(easing), 消除 3px 量化顿挫;
   - Shift+滚轮横向滚动;
   - 补上 `OnOffsetChange()` 调用(修注释不跟随 bug)。
2. **锚点缩放**
   - Ctrl+滚轮以鼠标位置为锚点缩放, 公式: `offset' = anchor/newScale - (anchor/oldScale - offset)`;
   - +/- 按钮缩放锚点改为视口中心, 删除 `UpdateScale` 内 `AdjustCenter()` 跳最左块的行为("重置"按钮保留居中跳转)。
3. **修横向滚动条** (`ScrollBar.lua`)
   - 滑块宽度公式补括号; 横向方向与纵向统一(反转); 滑块加最小尺寸。
4. **收紧滚动边界** (`Blockly:AdjustContentSize`)
   - `content_offset = -1000` 改为"内容包围盒 + 半个视口"的 margin, 并按 scale 换算视口逻辑尺寸。
   - 注意: 原注释提到 -1000 为兼容宏示教, 需回归测试宏示教录制/播放场景。

### P1 (已实施, 见本次提交)

5. **视口裁剪**: `RenderContent` 对顶层块做包围盒与视口相交判断, 不可见整链跳过; `Block:Render` 链内自上而下, 超出视口下边界提前终止, 完全在视口上方的块跳过自绘但继续递归。裁剪仅在工作区内容渲染时启用(工具箱/小地图/拖拽块不受影响)。
6. **减少 `painter:Flush()`**: 配合视口裁剪, Flush 只对可见块执行(第二轮修订: 保留逐块 Flush 以规避批渲染层序/卡顿风险, 次数已随裁剪大幅下降)。
7. **撤销快照去抖** (`Blockly:Do`): 工作区语句块数超过阈值(300)时, 全量 XML 序列化延迟 200ms 合并执行; `Undo/Redo` 前先冲刷待定快照, 语义不变。

### P1 未实施项

- **小地图缓存**: 需要渲染到纹理(render target)支持, 当前 painter 立即模式下无法逐帧跳过绘制(会闪烁), 建议后续在引擎层支持后再做。小地图默认关闭, 影响可控。

### P2 (产品层面, 待排期)

8. **强化"多头"教学路径**: 工具箱突出事件帽子块(当被点击/当按键/当收到消息); 默认示例改为多头写法。
9. **一键"整理块"**: 空白处右键菜单加 cleanup, 顶层堆栈按列自动排布。
10. **折叠入口前置**: 从右键菜单提升为块头部小三角按钮。
11. **小地图默认可见 + 双击块居中**: 块数超过阈值时自动显示小地图; 双击块自动滚动定位。
12. **触摸手势**: 双指平移/捏合缩放(当前只有 ToolBox 有触摸模拟滚动)。

## 四、修订记录

### 第二轮修复 (回归反馈: ① 滚动条拖拽无效果只能点击; ② 点头部块往左拖整段代码拖不动, 需先右移才能左移, 且拖动卡顿)

**根因**: 两个问题同源——当前偏移量(offsetX/offsetY)落在第一轮收紧后的滚动边界 [min, max] 之外。旧存档在 XML 里保存的偏移是按原 ±3000px 松边界记录的, 加载后直接超界; 居中定位/小地图跳转也可能把偏移设到界外。后果:
- 平移拖拽 `clamp(start+delta, min, max)` 把结果一直钳在边界上——往左拖纹丝不动, 往右拖出足够距离"回到"合法区间后左拖才恢复(现象②);
- 滚动条渲染的 ratio 超出 [0,1], 滑块被画到轨道外, 用户点的"滑块"实际命中跳转分支, 拖拽分支永远进不去(现象①)。

**修复**:
1. `AdjustContentSize` 计算完边界后, 将边界扩展到包含当前偏移——从界外位置可以平滑滚回内容区, 但不能滚得更远; 随着滚回, 边界自然收敛到内容边界(根治);
2. `ScrollBar:Render` 对 ratio 做 [0,1] 防御性钳制, 滑块永远画在轨道内;
3. 滚动条拖拽重写为"锚定内容偏移": 按下时记录 blockly 偏移单元数, 移动量按 range/free_track 比例直接换算, 不再经滑块位置往返换算; 滑块命中容差放宽 ±4px;
4. 恢复逐块 `painter:Flush()`(回退第一轮的统一 Flush, 排除批渲染改动的卡顿变量; 有视口裁剪后 Flush 只按可见块计, 原性能目标已达成)。

## 五、回归测试要点

- 缩放: +/- 按钮、Ctrl+滚轮, 观察视口是否保持锚点; 重置按钮仍应居中到最左块。
- 滚动: 滚轮平滑滚动、Shift+横向、拖拽平移、横/纵滚动条拖拽与点击跳转、注释(Note)跟随。
- 边界: 内容不应能被滑出可视范围超过半屏; **宏示教录制/播放场景**(content_offset 原值 -1000 的兼容目标)。
- 性能: 大工作区(300+ 块)拖块、滚动帧率; 撤销/重做正确性(快速连续操作后立即 Ctrl+Z)。
- 渲染: 长代码滚动时块进出视口无闪烁/残缺; 折叠块、拖拽中的块、工具箱、小地图显示正常。
